# 56. 合并区间

**难度：** 中等 · **状态：** 力扣已解答 · [原题](https://leetcode.cn/problems/merge-intervals/)

## 题目

以数组 `intervals` 表示若干个区间的集合，其中单个区间为 `intervals[i] = [startᵢ, endᵢ]`。请你合并所有重叠的区间，并返回 *一个不重叠的区间数组，该数组需恰好覆盖输入中的所有区间*。

**示例 1：**

> **输入：** `intervals = [[1,3],[2,6],[8,10],[15,18]]`  
> **输出：** `[[1,6],[8,10],[15,18]]`  
> **解释：** 区间 `[1,3]` 和 `[2,6]` 重叠，将它们合并为 `[1,6]`。

**示例 2：**

> **输入：** `intervals = [[1,4],[4,5]]`  
> **输出：** `[[1,5]]`  
> **解释：** 区间 `[1,4]` 和 `[4,5]` 可被视为重叠区间。

**示例 3：**

> **输入：** `intervals = [[4,7],[1,4]]`  
> **输出：** `[[1,7]]`  
> **解释：** 区间 `[1,4]` 和 `[4,7]` 可被视为重叠区间。

**提示：**

- `1 <= intervals.length <= 10⁴`
- `intervals[i].length == 2`
- `0 <= startᵢ <= endᵢ <= 10⁴`

## 我的答案

### 第一版：按左端点排序，再逐个合并

```python
class Solution:
    def merge(self, intervals: list[list[int]]) -> list[list[int]]:
        # 这里定义的问题是 对于重合的区间集合进行合并
        #首先第一步是进行排序 对于左区间

        intervals.sort(key = lambda x:x[0])
        ans = [intervals[0]] #这里是构建一个嵌套列表，就是列表里面元素还是列表
        if len(intervals) == 1:
            return intervals
        for str in intervals[1:]:
            #合并的条件是 原来集合最后一个元素大于新集合第一个元素
            if str[0] <= ans[-1][1]:  #这里错误的原因是一开始ans就是空列表
            #上述代码中，如果相等的话，也是需要合并。
                ans[-1][-1] = max(str[1],ans[-1][1])
            else:
                ans.append(str) #如果不合并，就直接在后面添加，用于下一个判断
        return ans
```

### 第三版：直接用 `intervals.sort()` 排序


## 我的注释与感悟

- **第三次尝试：不写 `lambda` 也能合并。** 区间是 `[左端点, 右端点]`，直接排序也会先看左端点。我观察到这次指定 `key` 的提交更快，想到的原因是：**明确只按左端点排序，就不需要比较整个区间。**
- **第一版和第二版的合并规则相同，只是分支顺序和第一个区间的处理不同。** 第一版先把第一个区间放入 `ans`，然后优先判断「能不能合并」；第二版从 `ans = []` 开始，优先判断「是否要直接追加」。`ans` 非空时，左端点 `>` 最后一个区间的右端点就追加，否则合并，所以**端点相等仍然要合并**。
- **`not ans` 必须放在 `or` 左边。** 当 `ans` 为空，`not ans` 为真，Python 会短路，不会去读 `ans[-1][-1]`。此时 `append` 是把第一个区间直接放进答案，不是与已有区间合并。
- **先按左端点排序，再把第一个区间放进 `ans`。** `ans` 是区间列表，`ans[-1]` 是最后一个已经合并出来的区间，`ans[-1][1]` 才是它的右端点。题目保证至少有一个区间，先放进去一个，就不会在第一次比较时对空列表取 `[-1]`。
- **只拿新区间和 `ans[-1]` 比。** 新区间的左端点 **小于或等于** 最后一个区间的右端点，就把它们合并；左端点不变，右端点取两者的最大值。比如 `[1,4]` 和 `[4,5]` 在 `4` 相接，也要合并。
- **有间隔就另起一区间。** 如果新区间的左端点更大，就把新区间追加进 `ans`。下一轮比较的是这个新加入的区间，而不用回头检查前面的区间。

## 知识点与评论

- **为什么排序后只看最后一个？** 新区间的左端点不会比 `ans[-1]` 的左端点更小，而 `ans` 中更早的区间都在 `ans[-1]` 的左边且与它不重叠，所以新区间不可能碰到更早的区间。若新区间和最后一个之间有间隔，后续区间的左端点只会更靠右，也填不上这个间隔。
- **合并时不能直接用新区间的右端点覆盖。** 例如 `[1,10]` 包含 `[2,3]`，合并结果仍是 `[1,10]`。用 `max` 才不会把原区间缩短。
- **复杂度与原地修改：** 排序最坏 `O(n log n)`，合并扫描 `O(n)`。第一版和第三版的 `intervals[1:]` 会产生 `O(n)` 的额外空间（不计结果）。`sort()` 会修改输入顺序，而且 `ans` 中存的是原区间列表的引用，修改右端点也会影响输入里的对应区间。

### 排序对比：`intervals.sort()` 与 `intervals.sort(key=lambda x: x[0])`

| 排序写法 | 力扣用例 | 执行用时 | 内存消耗 |
|---|---|---|---|
| `intervals.sort()`（截图 1） | 172 / 172 | 10 ms，击败 25.06% | 22.23 MB，击败 56.69% |
| `intervals.sort(key=lambda x: x[0])`（截图 2） | 172 / 172 | 5 ms，击败 75.74% | 22.10 MB，击败 71.73% |

**为什么两种都对？** Python 默认按字典序比较 `[左端点, 右端点]`：先比左端点，左端点相同才比右端点。`key` 版则只比左端点，左端点相同的区间保留原来的相对顺序。例如 `[[1,5],[1,3],[2,4]]` 默认排序会把 `[1,3]` 放在 `[1,5]` 前面，按 `key` 排序则不会交换这两个区间。本题的合并规则只要求左端点非递减，同起点如何排序都不影响结果 `[[1,5]]`。

**指定排序键为什么可能更快？** `key` 函数对每个区间只调用一次，排序时复用取出的整数键。比较单个整数，比每次比较两个列表、逐项检查端点更直接；左端点相同时也无需再比右端点。加速的关键是**只比较需要的排序键**，不是 `lambda` 语法本身。不过，提取和暂存这些键也有开销，两种排序的最坏时间复杂度都是 `O(n log n)`。

**怎么看提交数据？** 这两次提交里，`key` 版测得更快、内存数字也略低。但力扣统计的是整次提交，不是排序这一步；单次用时和整进程内存也会波动，不能据此断言 `key` 版总能快一倍或更省内存。这里推荐用 `key=lambda x: x[0]`，主要是因为它直接表达了「只按左端点排序」的意图。

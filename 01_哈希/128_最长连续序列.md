# 128. 最长连续序列

**难度：** 中等 · **状态：** 力扣已解答 · [原题](https://leetcode.cn/problems/longest-consecutive-sequence/)

## 题目

给定一个未排序的整数数组 `nums`，找出数字连续的最长序列（不要求序列元素在原数组中连续）的长度。

请你设计并实现时间复杂度为 `O(n)` 的算法解决此问题。

**示例 1：**

> **输入：** `nums = [100, 4, 200, 1, 3, 2]`  
> **输出：** `4`  
> **解释：** 最长数字连续序列是 `[1, 2, 3, 4]`。它的长度为 `4`。

**示例 2：**

> **输入：** `nums = [0, 3, 7, 2, 5, 8, 4, 6, 0, 1]`  
> **输出：** `9`

**示例 3：**

> **输入：** `nums = [1, 0, 1, 2]`  
> **输出：** `3`

**提示：**

- `0 <= nums.length <= 10⁵`
- `-10⁹ <= nums[i] <= 10⁹`

## 我的答案

### 解法一：直接用 `num` 向后找（截图版）

```python
class Solution(object):
    def longestConsecutive(self, nums):
        """
        :type nums: List[int]
        :rtype: int
        """
        max_length = 1
        nums_set = set(nums)
        if nums == []:
            return 0
        for num in nums_set:
            if num - 1 not in nums_set:
                cur_length = 1
                while num + 1 in nums_set:
                    num = num + 1
                    cur_length = cur_length + 1
                max_length = max(cur_length,max_length)
        return max_length
```

### 解法二：用 `cur_num` 向后找（文字版）

```python
class Solution:
    def longestConsecutive(self, nums: list[int]) -> int:
        max_length = 1
        nums_set = set(nums)
        if nums == []:
            return 0
        for num in nums_set:
            if num -1 not in nums_set:
                cur_max_length = 1
                cur_num = num
                while cur_num+1 in nums_set:
                    cur_num = cur_num +1
                    cur_max_length = cur_max_length +1

                max_length = max(cur_max_length,max_length)
        return max_length
```

## 我的总结与感悟

1. **先用集合去重，方便快速查找。** 最开始想过用 `nums.sort()`，但排序最坏需要 `O(n log n)`，不符合题目的要求。这里 `set(nums)` 只负责去重和加速查找，不排序；数字的连续性靠检查下一个数是否存在来判断。
2. **当前这一段的长度和历史最大值要分开。** 这是我觉得最重要的一点。每遇到新的起点，就把当前段的长度重新设为 `1`；扫完这段后，再用 `max(...)` 更新 `max_length`。如果把 `max_length` 也放在循环里反复初始化，就会丢掉之前找到的最大值。
3. **遍历结束后返回 `max_length`。** 它保存的是所有连续段中最大的长度，而不是最后一段的长度。

## 综合分析

两版的算法相同：用集合去重，只从没有前驱的数开始往后找。区别是第一版直接把 `num` 当作扫描变量，`num = num + 1` 不会修改集合，也不会影响 `for` 下一轮取值；第二版用 `cur_num` 单独记录扫描位置，保留 `num` 作为起点。

### 1. `set(nums)` 去重和加速查找，但不排序

`set(nums)` 把列表转为集合，例如 `[1, 1, 2, 3]` 转为 `{1, 2, 3}`。集合不保证按数值顺序遍历，打印时偶然看起来有序也不代表排序了。代码里的 `1 → 2 → 3 → 4` 是通过反复检查 `cur_num + 1` 是否存在找出来的，不是集合里的遍历顺序。集合成员查询平均 `O(1)`，列表查询最坏 `O(n)`；这一步让频繁查询变得便宜。

### 2. 只从没有前驱的数开始，避免重复扫描

如果 `num - 1` 在集合里，`num` 就不是起点，可以跳过。即使先遍历到了 `4`，也不用担心漏掉它：之后处理起点 `1` 时，会顺着找到 `2`、`3`、`4`。遍历集合而不是原列表也很重要：如果原列表里有许多个 `1`，直接遍历原列表会从同一个起点重复扫整段。

### 3. 当前段长度与历史最大值要分开

- `cur_num`：当前扫到的数字，从 `num` 开始逐个加一。
- `cur_max_length`：当前这一段的长度（不是最大值），每遇到一个新起点就重置为 `1`。
- `max_length`：目前处理完的所有段里，最大的长度。在 `for` 外初始化，每扫完一段就用 `max(...)` 更新。短段不会覆盖已有的长段。

这里的「全局」指**整个数组范围内的最大值**，不是 Python 的全局变量。三个变量都在 `longestConsecutive` 函数内。比如示例 1 有 `[1, 2, 3, 4]`、`[100]`、`[200]` 三段：无论先处理哪一段，最后保留的都是 `4`。

### 4. 为什么 `for` 里面套 `while` 仍然是 `O(n)`？

外层对每个不同的数检查一次前驱；内层只从起点出发。每个非起点的数最多被 `while` 成功扩展到一次，每段末尾再做一次失败检查。因此所有 `while` 的检查次数合起来也是 `O(n)`，不是每一轮 `for` 都扫一遍数组。加上建集合，**平均时间 `O(n)`，额外空间 `O(n)`**。你的空数组分支也正确：直接返回 `0`。

**复盘一句话：** 哈希集合让「找下一个数」更快，只从起点出发让「每段只扫一次」，段内计数和跨段取最大值负责得到最终答案。

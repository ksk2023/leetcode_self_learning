# 15. 三数之和

**难度：** 中等 · **状态：** 力扣已解答 · [原题](https://leetcode.cn/problems/3sum/)

## 题目

给你一个整数数组 `nums`，判断是否存在三元组 `[nums[i], nums[j], nums[k]]` 满足 `i != j`、`i != k` 且 `j != k`，同时还满足 `nums[i] + nums[j] + nums[k] == 0`。请你返回所有和为 `0` 且不重复的三元组。

**注意：** 答案中不可以包含重复的三元组。

**示例 1：**

> **输入：** `nums = [-1,0,1,2,-1,-4]`  
> **输出：** `[[-1,-1,2],[-1,0,1]]`  
> **解释：**  
> `nums[0] + nums[1] + nums[2] = (-1) + 0 + 1 = 0`。  
> `nums[1] + nums[2] + nums[4] = 0 + 1 + (-1) = 0`。  
> `nums[0] + nums[3] + nums[4] = (-1) + 2 + (-1) = 0`。  
> 不同的三元组是 `[-1,0,1]` 和 `[-1,-1,2]`。  
> 注意，输出的顺序和三元组的顺序并不重要。

**示例 2：**

> **输入：** `nums = [0,1,1]`  
> **输出：** `[]`  
> **解释：** 唯一可能的三元组和不为 `0`。

**示例 3：**

> **输入：** `nums = [0,0,0]`  
> **输出：** `[[0,0,0]]`  
> **解释：** 唯一可能的三元组和为 `0`。

**提示：**

- `3 <= nums.length <= 3000`
- `-10⁵ <= nums[i] <= 10⁵`

## 我的答案

### 第一次解答：排序 + 固定一个数 + 双指针

```python
class Solution(object):
    def threeSum(self, nums):
        """
        :type nums: List[int]
        :rtype: List[List[int]]
        """
        # 固定一个i作为循环 然后左右指针对向移动
        n  = len(nums)
        nums.sort() #最重要的前提是分类！
        ans = []
        if nums == []:
            return []

        for i in range(len(nums)):
            if nums[i] == nums[i - 1] and i > 0: #这里为了避免重复 当i相同的时候，就自动跳过
                continue
            if nums[i] > 0: #当nums[i]等于0的时候 肯定就不符合要求了
                break

            left = i + 1
            right = n - 1
            while left < right:
                if nums[i] + nums[left] + nums[right] == 0:
                    ans.append([nums[i],nums[left],nums[right]])
                    left  = left + 1
                    right = right - 1
                    while nums[left] == nums[left - 1] and left < right: #如果左指针一样的话，避免重复直接跳过，直到找到不一样的。
                        left = left + 1
                    while nums[right] == nums[right + 1] and left < right: #右指针同理
                        right = right - 1
                elif nums[i] + nums[left] + nums[right] > 0: #如果小了需要右移
                     right = right - 1
                elif nums[i] + nums[left] + nums[right] < 0: #如果大了需要左移
                     left = left + 1
                # if nums[left] == nums[left - 1] and nums[right] == nums[right + 1]:
                #     continue

        return ans
```

### 另一个写法：之前的版本（用 `j`、`k` 和 `s`）

```python
class Solution:
    def threeSum(self, nums: list[int]) -> list[list[int]]:
        nums.sort() #原地执行就行,不用赋值
        ans = []
        n = len(nums)
        # for i in range(n): 这个也是可以的
        for i in range(n-2):
            j = i + 1
            k =  n - 1
            if   i > 0 and nums[i - 1] == nums[i]: #这里i > 0的特殊情况就是说解决[ 0 0 0 ]的情况,此时nums[-1]==nums[2]==nums[0]
                continue
            while j < k:
                s = nums[i] + nums[j] + nums[k]
                if s > 0:
                    k -=1
                elif s < 0:
                    j += 1
                else:
                    ans.append([nums[i],nums[j],nums[k]]) # 这里才是最终提交的形式,append()
                    j += 1
                    while j < k and nums[j] == nums[j-1]:
                        j += 1
                    k -= 1
                    while j < k and nums[k] == nums[k+1]:
                        k -= 1
        return ans
```

## 我的注释与感悟

- **先排序，再固定一个数。** 固定 `nums[i]` 后，问题就变成在它右边找两个数，使它们的和等于 `-nums[i]`。从 `left = i + 1`、`right = n - 1` 开始，在 `left < right` 时查找，三个下标就不会重复。
- **和太大就缩小，和太小就增大。** 三数和大于 `0` 时，`right -= 1`，换成更小或相等的数；三数和小于 `0` 时，`left += 1`，换成更大或相等的数。这就是先排序的用处：知道移动哪边才有可能让和接近 `0`。
- **去重比较的是值，不是下标。** 外层如果 `nums[i]` 和前一个值相同，就不用再固定这个值找一遍。内层找到一组答案后，两边各向内移动，再跳过与刚用过的值相同的元素。题目不允许重复的是**整个三元组**，不是三元组里的数字；`[-1,-1,2]` 和 `[0,0,0]` 都可以是有效答案。

- **排序直接改原列表，找到一组就追加一组。** `nums.sort()` 原地排序，不需要接返回值。`ans.append([nums[i],nums[j],nums[k]])` 把三个数作为一个列表放进答案，而不是分别添加三个数。

## 知识点与评论

- **`i > 0` 是通用的边界判断，不只是针对 `[0,0,0]`。** 只有 `i > 0` 时，`nums[i - 1]` 才是当前元素的前一个值。`i = 0` 时，`nums[i - 1]` 实际上是最后一个元素；如果只比较两者的值就决定跳过，像 `[0,0,0]` 这样的输入会漏解。旧版把 `i > 0` 写在 `and` 左边，条件不成立时就不会访问 `nums[i - 1]`。
- **两版是同一种算法。** 旧版用 `range(n-2)` 保证固定的 `i` 右边至少还有两个位置，用 `s` 保存当前和，避免重复计算；找到答案后先移动左指针并去重，再处理右指针。第一份代码先移动两边再去重，并且多了 `nums[i] > 0` 的提前结束条件。两版的最坏时间复杂度都是 `O(n²)`。

- **原注释保留，两个地方以代码条件为准。** `nums[i] > 0` 才能提前结束；等于 `0` 仍可能得到 `[0,0,0]`。另外，原注释里「大了」「小了」写反了，代码方向是对的：**和偏大，右指针左移；和偏小，左指针右移。**
- **为什么移动一侧不会漏解？** 固定 `i` 后，如果当前和偏大，保留 `right`、再把 `left` 向右移，和只会更大或不变，所以当前 `right` 可以排除。和偏小时同理：保留 `left`、把 `right` 向左移，和只会更小或不变。
- **时间复杂度：** 排序最坏 `O(n log n)`；每次固定 `i` 后，两个指针最多走 `O(n)` 步，总时间为 `O(n²)`。

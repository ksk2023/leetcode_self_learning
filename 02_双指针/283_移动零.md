# 283. 移动零

**难度：** 简单 · **状态：** 力扣已解答 · [原题](https://leetcode.cn/problems/move-zeroes/)

## 题目

给定一个数组 `nums`，编写一个函数将所有 `0` 移动到数组的末尾，同时保持非零元素的相对顺序。

**请注意**，必须在不复制数组的情况下原地对数组进行操作。

**示例 1：**

> **输入：** `nums = [0,1,0,3,12]`  
> **输出：** `[1,3,12,0,0]`

**示例 2：**

> **输入：** `nums = [0]`  
> **输出：** `[0]`

**提示：**

- `1 <= nums.length <= 10⁴`
- `-2³¹ <= nums[i] <= 2³¹ - 1`

## 我的答案

### 第一次解答：双指针交换

```python
class Solution:
    def moveZeroes(self, nums: list[int]) -> None:
        """
        Do not return anything, modify nums in-place instead.
        """
        left = 0
        for right in range(len(nums)):
            if nums[right] != 0 :
                nums[left],nums[right] = nums[right],nums[left]
                left = left + 1
        return nums
```

### 第二次解答：把 `right` 写成了元素值（未通过）

```python
class Solution:
    def moveZeroes(self, nums: list[int]) -> None:
        """
        Do not return anything, modify nums in-place instead.
        """
        left = 0
        for right in nums:
            if right != 0:
                nums[left],right = right,nums[left]
                left = left + 1

        return nums
```

## 我的注释与感悟

> 使用双指针  
> 因为目的是想要将所有的0移动到后面 所以做法是设置左右指针 右指针当遇到不是0的时候 和左指针进行互动 互动之后左指针进行右移 右指针不是0就互换左指针右移 右指针是0就右移

### 第二次复盘

**我的理解：先分清 `right` 是 `nums` 里的一个值，还是序列编号（下标）。两者的意义不一样。**

- `for right in nums`：`right` 是**元素值**，直接用 `right` 判断是不是 `0`；给 `right` 赋值不会改动数组里的元素。
- `for right in range(len(nums))`：`right` 是**序列编号（下标）**，`nums[right]` 才是这个位置上的值。要原地交换两个位置，就写 `nums[left], nums[right] = nums[right], nums[left]`。

例如示例里的 `12`，**值是 `12`，下标是 `4`**。我要和左指针所在的位置交换，用的是下标 `4` 对应的 `nums[4]`，不是把 `12` 当成下标。

**分清值和下标后，再看两种操作：**
- **遇到 `0`：只移动右指针。** `left` 不动，`for` 循环会自动推进 `right`。
- **遇到非 `0`：先交换，再让 `left` 加 `1`。** 交换的是 `nums[left]` 和 `nums[right]` 这两个位置，而不是数组里的一个位置和变量 `right`。之后 `right` 仍由循环推进。

## 第二次提交：错误案例与排查

- **输入：** `[0,1,0,3,12]`
- **实际得到：** `[1,3,12,3,12]`
- **预期结果：** `[1,3,12,0,0]`

**从第一次应该交换的地方排查。** 当循环读到第二个元素时，`left` 是 `0`，`right` 的值是 `1`（这次碰巧也等于该元素的下标）。执行 `nums[left],right = right,nums[left]` 后，`nums[0]` 被写成 `1`，原来的 `0` 只赋给了局部变量 `right`，并没有写回 `nums[1]`。所以数组立刻变成 `[1,1,0,3,12]`，下一轮循环还会重新给 `right` 赋值。后面也一样：非零值被搬到了前面，但交换的另一半没有写回数组。

**怎么修：** 交换两处元素需要两个下标。用 `range(len(nums))` 让 `right` 表示位置，用 `nums[right]` 取得该位置的值。如果想同时拿到下标和值，也可以用 `for right, value in enumerate(nums)`。下面是修正版；去掉 `return nums` 是为了符合 `-> None` 的约定，不是此次错误的根因。

```python
class Solution:
    def moveZeroes(self, nums: list[int]) -> None:
        left = 0
        for right in range(len(nums)):
            if nums[right] != 0:
                nums[left], nums[right] = nums[right], nums[left]
                left += 1
```

## 知识点与评论

- **两个指针的分工：** `right` 逐个扫描元素；`left` 指向下一个非零元素应该放的位置。`right` 遇到 `0` 时，`left` 不动，`for` 循环会继续推进 `right`。
- **为什么不会打乱顺序？** 非零元素按原顺序被 `right` 遇到，也按这个顺序放进 `left` 指向的位置。当 `left < right` 时，`left` 所在的位置是 `0`；当 `left == right` 时，元素和自己交换，不影响结果。
- **原地修改与返回值是两回事：** 交换已经改了原数组，算法正确。原解末尾的 `return nums` 和 `-> None` 不一致；按题目的函数约定，可以去掉这一行，函数会隐式返回 `None`。笔记保留第一次的写法。
- **复杂度：** 遍历一趟，时间 `O(n)`，额外空间 `O(1)`。

# 560. 和为 K 的子数组

**难度：** 中等 · [原题](https://leetcode.cn/problems/subarray-sum-equals-k/)

## 题目

给你一个整数数组 `nums` 和一个整数 `k`，请你统计并返回 *该数组中和为 `k` 的子数组的个数*。

子数组是数组中元素的连续非空序列。

**示例 1：**

> **输入：** `nums = [1,1,1], k = 2`  
> **输出：** `2`

**示例 2：**

> **输入：** `nums = [1,2,3], k = 3`  
> **输出：** `2`

**提示：**

- `1 <= nums.length <= 2 * 10⁴`
- `-1000 <= nums[i] <= 1000`
- `-10⁷ <= k <= 10⁷`

## 我的答案

### 第一版：双层循环暴力枚举

```python
class Solution:
    def subarraySum(self, nums: List[int], k: int) -> int:
        # 子数组是连续的 使用双层循环暴力解法
        count = 0
        # 外层固定子数组的起点 left，每换一个起点，就把当前区间的和清零。
        for left in range(len(nums)):
            sum = 0

            # 内层从 left 开始逐个推进 right，先检查单个元素，再向右扩展。
            for right in range(left,len(nums)):
                # 在上一轮的和上加上新进来的元素，得到 nums[left:right+1] 的和。
                sum = sum +nums[right]
                if sum == k :
                    count = count + 1
                    # sum = nums[right]
                    # 找到一个后不重置 sum，也不退出内层循环；同一起点还可能有其他答案。
        # 所有起点和终点都检查完后，返回累计的个数。
        return count
```

### 第二版：前缀和 + 哈希表

```python
class Solution:
    def subarraySum(self, nums: List[int], k: int) -> int:
        #使用前缀和思路
        pre_fix = {0:1}
        sum = 0
        count = 0
        for num in nums:
            sum = sum + num
            if sum - k in pre_fix: # 结果其实是要先查询再更新哈希表 因为我们要找的是当前位置之前出现过的前缀和。
                count = pre_fix[sum - k] + count
            if sum not in pre_fix:
                pre_fix[sum] = 1
            else:
                pre_fix[sum] = pre_fix[sum] + 1

        return count # 这个不能再内部啊
```

### 第三版：前缀和 + 哈希表（含公式推导）

```python
class Solution:
    def subarraySum(self, nums: List[int], k: int) -> int:
        prefix = {0:1}
        cur_sum = 0
        ans = 0 #统计出现个数
# 前缀和核心原理是，将要求子数组 nums[i...j] 的和等于 k。用前缀和表示就是：
# 前缀和(j) - 前缀和(i - 1) = k
# 移项一下：
# 前缀和(i - 1) = 前缀和(j) - k
# 翻译成大白话：当我们走到位置 j，算出当前前缀和是 sum 时，只需要看看之前有没有出现过前缀和为 sum - k。
        for num in nums:
            cur_sum = cur_sum + num

            if cur_sum - k in prefix:
                ans = prefix[cur_sum - k] + ans #迭代处理总出现个数
            if cur_sum in prefix:
                prefix[cur_sum] += 1 # 如果出现一次，就加一，统计计算一次
            else:
                prefix[cur_sum] = 1 #如果不在的话，就重新赋值为1

        return ans
```

第三版和第二版是同一种算法，都是**先查 `cur_sum - k` 的历史次数，再更新当前前缀和的次数**。原注释中的「前缀和(j)」指累加到下标 `j`（含 `j`），对应下文按元素个数记的 `P[j + 1]`；两种记法只是下标定义不同。

## 我的注释与感悟

### 第一版：枚举起点和终点

- **外层固定起点，内层枚举终点。** 每一对 `left`、`right` 都对应一个连续非空子数组，所以不会漏掉只有一个元素的子数组，也不会重复数同一个区间。
- **当前区间和每换起点就清零，答案计数跨起点保留。** 内层每往右走一步，只加上新元素；和等于 `k` 就把 `count` 加 `1`，再继续往右找。

### 第二版：先查以前的前缀和，再登记当前前缀和

- **把找区间改成找前缀和。** 设 `P[i] = sum(nums[:i])`，表示前 `i` 个元素的和，`P[0] = 0`。扫到下标 `right` 时，代码里的 `sum` 是 `P[right + 1]`。区间 `nums[left:right+1]` 的和等于 `P[right + 1] - P[left]`，所以只要找以前有没有 `P[left] = sum - k`。代码中只维护一个滚动的 `sum`，不用另外造一个前缀和数组。
- **哈希表存的是「前缀和 → 出现次数」。** 先查 `sum - k`：它之前出现了几次，就有几个不同的起点能和当前终点配对，`count` 就加几。然后更新的是**当前的 `sum`**：存在就把频次加 `1`，不存在就新建并记为 `1`。不管这轮有没有找到答案，都要登记当前前缀和，留给后续位置查。
- **初始化 `{0: 1}`，是为了数到从下标 `0` 开始的子数组。** 还没读任何元素时，起点之前的前缀 `P[0]` 已经出现过一次。如果当前 `sum == k`，查 `sum - k` 就是在查这个 `0`。这条记录是一个起点，不是把空子数组算进答案。
- **先查再更新，最后才返回。** 查表时只允许配对到当前前缀之前的位置，才能保证子数组非空。`return count` 放在 `for` 外，等所有可能的右端点都统计完再返回。

### 为什么不能先更新：`nums = [0]`、`k = 0`

这个输入只有一个非空子数组 `[0]`。读到第一个 `0` 后，当前前缀和是 `P[1] = 0`，要查的 `sum - k` 也是 `0`。

| 执行顺序 | 查询时的哈希表 | 算出来的个数 |
|---|---|---:|
| **先查询，再更新** | `{0: 1}`，只有数组开始前的 `P[0]` | `1`，对应 `nums[0:1]` |
| 先更新，再查询 | `{0: 2}`，同时包含 `P[0]` 和刚登记的 `P[1]` | `2`，多算了 `nums[1:1]` 这个空区间 |

**两个前缀和的值可以相同，但位置不能相同。** 正确的那一轮在查询完之后也会把表更新成 `{0: 2}`，只是这条新记录要等到后面的下标才能参与配对。

## 知识点与评论

- **第二版的复杂度：** 每个元素只做一次累加、一次查询和一次频次更新，平均时间 `O(n)`，额外空间 `O(n)`。
- **命中后仍要继续枚举。** 例如 `nums = [0,0]`、`k = 0`，固定 `left = 0` 时，`right = 0` 和 `right = 1` 都是答案，不能在第一次命中后 `break`。数组也允许负数，当前和超过 `k` 时，后面仍有可能降回 `k`。
- **累加省去了重复求和，但没有减少区间数量。** 每个区间只做一次加法和比较，时间仍是 `O(n²)`，额外空间是 `O(1)`。当 `n = 20,000` 时，要检查 `200,010,000` 个区间，这就是大输入容易超时的原因。
